# mother

Telegram-бот, который готовит видео и раз в день присылает JSON-план. Ничего не
публикует, не обращается к VK, не хранит токенов. Независим от omega (код скопирован
и адаптирован, импортов из omega нет).

## Что отдаёт

В `DELIVER_HOUR:DELIVER_MINUTE` МСК (на сервере 09:00, подготовка `PREPARE_HOUR` в 08:00) — план в Telegram и по API для ПК:

```json
{"id": 1, "accounts": [{"id": 1234567, "profile": "682d1e9fb6f4", "groups": [
  {"id": 2343, "videos": [{"id": 1, "path": "/c/video/video1.mp4"}]}]}]}
```

- `id` — номер плана (растёт на 1 при каждой выдаче);
- `accounts[].id` — страница VK аккаунта (vk.com/id1234567), `profile` — профиль ManyFaces на ПК, в котором
  выполнен вход в неё (`null` — профиль по умолчанию); группы без аккаунта собираются в аккаунт с
  `"id": null, "profile": null`;
- `groups[].id` — числовой id группы VK (бот находит его по ссылке);
- `videos[].id` — id записи в очереди; `path` = `OUTPUT_PATH_PREFIX` + имя файла в `VIDEO_DIR`.

ПК по API получает тот же план с названиями аккаунтов и групп и описаниями видео.

## Аккаунты (мультиаккаунт)

Аккаунт — страница VK и профиль ManyFaces на ПК, в котором выполнен вход в неё.

🧑‍💻 **Аккаунты** → «➕ Добавить аккаунт» → ссылка на страницу VK (`vk.com/id123`, `vk.com/имя` или число).
Бот проверяет её так же, как группу: открывает публичную страницу и берёт оттуда id и имя («Нашёл:
«Имя Фамилия» (id …). Сохранить?»); ссылку на сообщество, удалённую или несуществующую страницу не
примет. Затем бот кнопками предлагает профиль ManyFaces — из списка, который присылает ПК
(`POST /profiles`, только id и название; при каждом `pull_plan.py pull` и командой `pull_plan.py profiles`),
или «профиль по умолчанию». Сменить профиль потом — кнопка «🖥 Профиль» у аккаунта; «🖥 Профили на ПК»
показывает список с ПК.

Группа привязывается к аккаунту кнопкой 🧑‍💻 в 👥 Группы (сразу после добавления группы бот тоже спросит).
Удалить аккаунт — его группы остаются, но без аккаунта.

Если готовых видео нет — приходит сообщение «план пуст», пустой JSON не отправляется.

## Как работает

1. В боте: 👥 группы → 🎬 источники (TikTok-аккаунт или база парсера) → 📋 правила
   (источник → группа, N видео в день).
2. В `PREPARE_HOUR` (на сервере 08:00 МСК, и при старте) — подготовка: берётся остаток дневной нормы по каждому
   правилу, видео скачиваются (yt-dlp), прогоняются через ffmpeg (если включено
   `/process`) и кладутся в `VIDEO_DIR/video<id>.mp4`.
3. В час выдачи (на сервере 09:00 МСК) — сборка и отправка JSON, видео помечаются выданными.
4. Если бот был выключен в час выдачи — при старте выдаст план, как только он включится
   (только если сегодня план ещё не отправлялся и есть готовое).

## Запуск

```bash
pip install -r requirements.txt      # + ffmpeg/ffprobe в PATH
cp .env.example .env                 # заполнить TELEGRAM_TOKEN (новый бот из BotFather)
python bot.py                        # запускать из папки mother
python -m pytest                     # тесты (без сети)
```

## Команды

`/start`, `/status`, `/plan` (выдать план сейчас; если очередь пуста — сначала
подготовит), `/plan 2` (ещё 2 видео по каждому правилу сверх дневной нормы, до 10),
`/nolimit N` (или `/plan nolimit N`) — N видео по каждому правилу **без дневной нормы**, до `NOLIMIT_MAX`
(500). Готовится в фоне, бот остаётся отзывчивым; план приходит, когда всё скачано. Повторов нет, норма
следующего дня не уменьшается; перед началом проверяется, хватит ли места на диске (`NOLIMIT_MB_PER_VIDEO`,
20 МБ на видео), `/resetquota` (обнулить дневную норму ближайшего дня выдачи: нужно в период тестов, потому что ручные `/plan` засчитываются в норму завтрашней выдачи и могут оставить её пустой; уже выданные видео не повторятся), `/errors`, `/stop` / `/startBot` (пауза автоматики, только `ADMIN_IDS`),
`/process <off|ultrafast|superfast|veryfast|faster> [down|nodown]` (только `ADMIN_IDS`).

## Уведомление об итоге выкладки

Когда ПК присылает итог выкладки (`POST /plan/<id>/result`), бот в течение ~20 секунд пишет в Telegram сводку: сколько видео выложено, какие не вышли и почему и что не скачалось на ПК. Сервер записывает итог в базу, а бот раз в 20 секунд проверяет, о чём ещё не сообщил: уведомление не теряется при перезапуске бота и повторяется, если Telegram был недоступен. Итоги, пришедшие до появления этой функции, повторно не присылаются.

## Повтор не вышедших видео

Если в итоге выкладки есть видео, которые не вышли по причине, которую может исправить повтор (VK отказал,
сбой на странице, прогон прервался), под уведомлением появляется кнопка «🔁 Перевыложить не вышедшие (N)».
Нажатие создаёт новый план-повтор (свой номер, `"retry_of": <номер исходного>`) только из этих видео, с теми же
файлами и описаниями. ПК раз в 5 минут спрашивает `GET /plan/retry` и, если повтор есть, сразу выкладывает его;
итог приходит отдельным уведомлением «Выкладка плана №N (повтор плана №M)», и под ним снова будет кнопка, если
что-то опять не вышло.

Не повторяются: выложенные; `pending` (нажато «Опубликовать», но выход не подтверждён — клип мог выйти, повтор
дал бы дубль); ошибки самого файла (длиннее 3 минут, нет видеодорожки) и группы вне списка разрешённых на ПК.
Повтор для плана создаётся один раз; файлы, нужные невыложенному повтору, ежедневная очистка не удаляет.
Ежедневная выдача (`/plan/latest`) повторы не отдаёт — они идут отдельно.

## Структура

| Файл | Назначение |
|---|---|
| `bot.py` | Telegram-интерфейс, точка входа |
| `scheduler.py` | планирование правил, подготовка видео, выдача плана, джобы |
| `plan_builder.py` | сборка JSON (чистая функция) |
| `db.py` | SQLite (`data/mother.db`) |
| `config.py` | настройки из окружения |
| `downloader.py`, `video_processor.py` | скачивание и ffmpeg |
| `source_reader.py`, `account_source.py`, `parser_tiktok.py` | чтение и парсинг источников |
